# Obsidian Memory Kit

继续在你喜欢的官方应用聊天，让能访问本机的助手把原话和决定留在你自己的 Markdown 库里。举例来说，你在模型甲拒绝了中午观察兰花的建议，第二天在模型乙确定早上八点观察。两份原话分别保存，从一篇「兰花观察课」就可以追到这两个决定。

## 十分钟试一遍

需要 macOS 或 Linux、Python 3.9+。用 Obsidian 打开库可以点击双链，也可以直接读 Markdown。无需账号、API 密钥或付费服务。

下载仓库 ZIP 并解压，或使用 GitHub 的模板复制功能（发布者需先在 GitHub 开启该选项）。在仓库目录打开终端。也可以把下面步骤交给本地助手，告诉它「接手这个库，用两个示例演示怎么找回决定」。

```sh
# 创建独立演示库。选择一个尚不存在的位置。
demo="$HOME/MemoryKit-Demo"
test ! -e "$demo" && cp -R vault "$demo"
python3 tools/memory.py --vault "$demo" import examples/01-orchid.md
python3 tools/memory.py --vault "$demo" import examples/02-orchid.md
python3 tools/memory.py --vault "$demo" handoff 兰花观察课
```

在 Obsidian 的「打开本地仓库」选择刚复制的 MemoryKit-Demo。打开「02 模型对话 → 主题记录 → 兰花观察课」。问助手 **「我为什么最后选了早上？我采纳过每天中午拍照的建议吗？」** 回答应能引用两条用户原话：因为上课放弃中午，选择出门前容易坚持的早晨。每条摘录都有原文链接。再导入一次，相同发言仍只有一份。

## 接自己的聊天

- **本地助手。** 启用持续记录后，为可读取的讨论生成下述 Markdown，使用相同的对话和消息标识；话题有实质进展时调用 import。查看原记录和主题索引后再作答。此工具处理提供给它的文件，没有平台账号抓取功能。
- **各平台官方客户端。** ChatGPT 支持导出的 conversations JSON、含它的 ZIP、数字分片。读取当前可见分支，跳过已归档对话、内部工具消息和不可见分支，非文本附件标注状态。其他客户端可以导出 Markdown，或让模型按下方格式提供。可用的平台导出接口取决于你自己的账号和客户端。
- **历史批量。** 先运行 `python3 tools/memory.py --vault "$demo" preview 导出.zip`。检视对话标题、数量与指纹，确认后再运行 `import 导出.zip --approve 打印出的指纹`（同一命令前缀）。普通单条文件直接 import。同一对话按平台和原始标识去重；旧版笔记能逐条对齐时原页续写，对不齐则暂停。
- **收件箱。** 选库外的空目录，只投入你要处理的文件。手动运行 `python3 tools/memory.py --vault "$demo" scan "$HOME/模型对话收件箱"`。原始投递文件保留在收件箱中，由你决定清理。分类不明、批量待确认或疑似包含凭据的文件留在原处。用 status 查看原因，让本地助手代为处理。
- **macOS 登录后自动处理。** 运行 `python3 tools/mac_agent.py install --vault "$demo" --inbox "$HOME/模型对话收件箱"`。安装器用 Apple 命令行开发工具编译具名的本地收件箱应用。macOS 如询问是否允许它访问“文稿”，允许所选目录的访问即可。每分钟检查，等文件连续两次稳定再导入。有需核对的文件时本地通知；成功时安静。运行 `python3 tools/mac_agent.py remove --vault "$demo"` 可关闭。Linux 使用 scan 或自己的定时任务。
- **找回和接续。** `find 关键词` 可搜索七个主题入口；`handoff 主题名` 在本地输出带出处的决定、更正、待办和近期上下文。发送到网页模型前先筛选本人愿意分享的内容。网页模型看不到本地双链，引用摘录可随接续说明一起复制。

### 通用 Markdown

```markdown
---
platform: 示例平台
conversation_id: orchid-week-2
category: 学习
topic: 兰花观察课
date: 2025-03-03
---
# 讨论记录频率

## 我 · m01
我决定周一到周五都记录。

## 助手 · m02
周末需要单独注明。
```

分类支持工作、学习、生活；缺少分类时只用本地词表判断，无法确定的条目等待核对。优先写明 topic 来连接同一个项目。可对单条来源用 `--category 学习 --topic 兰花观察课`。工作进入 `work/项目方案`，学习进入 `02 模型对话/学习`，生活进入 `diary/主题整理/生活记录`。已有同路径主题保留原正文，工具只更新标记之间的区域。「我的批注」保留在区域外。专题摘录由可追溯原句组成，助手需要时再回原文综合。涉及多个独立主题可让助手分别整理主题记录，通用导入器当前每条对话采用一个主题。

可用 `## 我` 和 `## 助手` 标注发言。推荐提供稳定的原对话和消息标识；缺省使用标题和发言位置，适合只从末尾追加的来源。无说话者标题的普通 Markdown 按「来源文本（说话者待核实）」保存。内容缺少足够日期时，笔记日期可能是导入日。请保留原始日期。

### 更正、排除与隐私

用新的用户发言注明「更正」「我改为」，旧判断与新说法都能查到。单独发送「这段别记」会排除紧邻的上一轮交流、该条指令以及到下一次用户发言前的模型响应。要排除更早的指定消息，在 Markdown 属性区加入 `omit: m01 m02`，列出所有相关消息标识。不要把密语放在标题或元数据。对于超出上述简单指令的范围，请让助手先确认涉及哪些消息。

排除会同步更新本工具管理的原文、主题摘录、接续说明和本机状态；后续重复导入仍保持排除。未管理的旧笔记、你自己写的批注、外部源文件、历史备份和已经发出去的文字需要分别处理。凭据筛查仅识别常见模式，投递前仍要检查敏感内容。中途失败后用相同文件重试。程序在库外的用户专属状态目录保留已筛选原文、标识、排除记录和待恢复事务；备份时将它与私人库一起保存，勿放进公开仓库。默认位置为 `~/Library/Application Support/ObsidianMemoryKit/`（Linux 也可用 --state-dir 指定私有路径）。

## 维护和公开

仓库中的 vault 是空白模板；请从其副本开始记录。在全新目录运行以下命令：

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_public.py
```

发布时只使用检查通过的文件清单和虚构示例，另行确认目标仓库、可见性和 Git 历史。模板与工具采用 MIT 许可证。
